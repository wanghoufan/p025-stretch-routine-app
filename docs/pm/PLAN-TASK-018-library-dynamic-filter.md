## 代码事实复核

TM 所列现状总体准确，补充与纠正如下：

1. `ActionFilterBar.tsx` 当前确为名称搜索框加难度单选 chips（全部/低/中/高），chips 使用 `radiogroup/radio`，但 chip 高度仅 `36`，低于项目 `MIN_TOUCH_SIZE=48`。
2. `actionGroups.ts` 当前按固定顺序输出拉伸/热身/核心训练；场景判定为热身优先、核心其次、其余拉伸。只有拉伸生成二级部位组，热身和核心训练直接使用 `actions`。
3. `seeds.ts` 中三类场景动作均有多部位数据；热身含全身/肩/腿/腰腹等，核心训练含腰腹/髋臀/背等。带“热身+核心”的登山跑按现规则只归热身。
4. `bodyPartOfAction()` 当前按 `BODY_PART_GROUPS` 固定顺序取第一个规范部位；无标签或只有未知标签均归“其他”，所以每个动作当前只进入一个二级组。
5. `ActionFilters` 当前只有 `{ difficulty, query }`；难度或搜索激活后，未被用户显式覆盖的现存组默认展开。显式折叠状态会跨筛选变化保留。
6. 现有 `groupActions()` 先全局过滤，再删除无命中场景；场景 badge 统计唯一动作数。B-4 的“多部位重复计数”不是当前能力。
7. `src/tests/domain/actionGroups.test.ts` 与 `src/tests/integration/libraryFilter.test.tsx` 均硬编码了难度筛选、拉伸二级分组或首部位唯一归属，必须同步改造。

## 设计审查结论

结论：B-4 的方向和现有代码结构兼容，可在 `actionGroups.ts` 的纯函数、`ActionFilterBar.tsx` 的受控输入及 `ActionLibraryScreen.tsx` 的页面状态内完成，不需要数据库迁移、依赖新增或产品 Plan 重开。但口径 3 与口径 9 组合后仍缺一个阻塞定义，见 `HD-1`。

### 已确定边界及建议解法

1. **活动组被收起**：活动场景不因收起而改变，chips 继续归属最后一次“由收起变展开”的场景。只有用户展开另一个场景时才切换活动场景。这样无需维护展开历史栈，且严格符合“最后点开（展开）”。界面须显示当前归属（如“拉伸部位”），避免 chips 控制不可见组时语义不明。
2. **初始活动组**：固定为拉伸，不以搜索后 `groups[0]` 代替。否则搜索令拉伸消失时活动场景会暗中跳转。
3. **切换活动组**：展开另一组时切换活动场景，并把部位选择重置为“全部”；不跨场景保留同名部位，避免新场景不存在该选项或出现隐式过滤。多组仍可同时展开，不做手风琴。
4. **chips 的数据源**：按活动场景的完整动作集合生成，位于搜索和部位筛选之前；只按该场景是否存在规范部位命中决定 `count>0`。搜索、当前所选部位不得让 chips 自己消失或改变顺序。
5. **活动组筛后为 0**：该场景组按现有“空组隐藏”规则从列表消失；chips 保持原活动场景和稳定选项，不随结果为 0 而收缩。若所有场景均无结果，显示现有空结果态。清除筛选须同时清空搜索和部位选择，但活动场景仍保留。
6. **搜索与部位不同时命中**：全局搜索先作用于所有场景；活动场景再与部位条件取 AND，故搜索命中但部位不命中的动作不在活动场景显示；非活动场景只受搜索影响，保持全量部位。活动场景可能因此隐藏，其他搜索命中场景仍显示。
7. **无部位标签动作**：“其他”定义为动作的 `bodypart` 与 `BODY_PART_GROUPS` 无交集，包括 `undefined`、空数组及只有未知/历史脏标签；若同时含至少一个规范部位，则不归“其他”。“全部”包含该场景全部唯一动作，“其他”只包含上述无规范部位动作。
8. **“其他”是否常驻**：不常驻。仅当活动场景完整动作集合中至少有一个“其他”动作时，追加在固定规范部位之后；搜索无命中不会令其消失。
9. **动作编辑/删除后的失效选择**：数据刷新后若当前所选部位不再存在，自动回退“全部”，不得留下无对应 chip 的隐藏状态。
10. **分组与渲染**：三个场景均平铺动作卡片，不再产生或渲染 `ActionBodyPartGroup` / `library-subgroup-*`。场景归属规则及热身优先级不变。
11. **难度范围**：只删除动作库筛选状态、chips 和相关文案；`Action.difficulty`、标签词表、持久化、动作编辑器、种子难度和流程模板难度角标均不动。
12. **自动展开**：名称搜索维持现有“命中组默认展开、显式折叠优先”的行为；部位筛选只针对活动场景，不得把其他折叠组自动展开。若活动场景被用户显式收起，选择 chip 不强行展开。

### 无障碍与触控规范

## Risks

- **R1｜规格矛盾**：平铺列表下“动作出现在多个部位下/组头重复计数”可能意味着重复卡片、唯一卡片或多选交集；未完成 `HD-1` 就实现会导致 Reviewer/QA 无统一判据。
- **R2｜动态选项抖动**：若 chips 从搜索后结果生成，输入搜索词会令选中 chip 消失。以场景完整集合生成并对失效选择回退可规避。
- **R3｜活动场景漂移**：若使用过滤后第一个 group 推导活动场景，搜索会隐式改变 chips 归属。活动场景必须使用独立 state。
- **R4｜作用域串扰**：若继续把所有筛选塞进一次全局 `groupActions()`，部位条件容易误伤非活动组。纯函数须显式接收活动场景/部位或分两阶段处理。
- **R5｜React key/操作歧义**：若最终选择重复渲染同一动作卡片，现有 `key={action.id}` 会冲突，且同一编辑/删除入口重复出现；必须在 `HD-1` 中明确接受并定义 key 与 badge 规则。
- **R6｜旧回归假绿/假红**：旧测试硬编码难度 ID、二级分组和唯一首部位规则；仅新增测试而不改旧测试不可验收。

【请你决策】
选择以下一种验收口径：

1. **A｜单选、唯一卡片（建议）**：一次选择“全部”或一个部位；多标签动作选择任一对应部位都能出现，但同一画面只出现一次；场景 badge = 当前实际显示的唯一动作卡片数。“重复计数”理解为该动作可分别计入多个部位的候选集合，不在同一平铺结果重复。
