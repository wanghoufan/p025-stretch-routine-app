- 语音可用性依赖三件设备侧一次性状态：默认引擎设置（`tts_default_synth`）、引擎是否装中文语音包、是否联网——三者均不在任何 DoD/自检清单中，三次引擎漂移全部发生在「让声音先出来」的救火语境。09-17 的「离线满足」正是无设备基线的判定（C2）。
- **下次怎么说**：「先在我这台真机上确认系统默认 TTS 引擎是什么、断网能不能出声，把结果写进验收标准再定方案。」
- **责任**：开发者应建环境自检；平台限制（国行小米无离线中文引擎）非过错，但未验证即下结论是流程缺陷。

### G10｜对外资产所有权规则缺失（README 事故的机制层）

- 同一 `README.md` 被两套模板声明所有权（产品门面 vs 治理脚手架入口），铺包按整目录覆盖、无「同名文件已存在则保护」规则；两次覆盖未进 Git 而在工作区静默发生；最终治理版经 `8f8e43e` 合法化入库，同提交 `.gitignore` 屏蔽 `*.旧版-*`——**未来任何铺包覆盖都不会再在 `git status` 显形**（A 8.2 之 4，采纳）。
- **返工代价**：产品门面（含分发短链、安装说明）在仓库首页消失；`README.en.md` 仍是产品英文版、中英不对称，英文读者看到产品、中文读者看到脚手架。
- **预防**：铺包规则需显式声明实例层文件清单（哪些文件属于项目所有、铺包前必须 diff）。

### G11｜设备/验收证据无基线卡（A2/A3 采纳）

- 同一序列号 `IN9LZTAYV4UGU4JF` 被记为 Android 14（09-17）与 Android 12/SDK 31（09-27），与 OTA 方向相悖，至少一处笔误（I）；`indq5xfi6hovay4d` 在两份 QA 中机型标识不一致（ruby/22101316C vs Redmi Note 12 Pro——两者或为同机异名，但仓内无对照说明）。
- **差距**：QA 报告无统一设备基线卡（序列号+型号+系统版本一次性登记、后续引用），证据链可信度受损。
- **预防**：每轮真机 QA 头部强制引用同一设备卡，版本字段以现场 `getprop` 输出为准。

### G12｜「代码级证据放行」常态化

- 完成页「用时」与统计页同源一项目前**只有代码证据、没有屏幕证据**：真机对照标 ⚠「未取到直接对照」，改由 code-reviewer 以代码级证据放行、真机对照列 P2 挂账（`task021-真机第一轮.md`）。这与全局纪律「静态代码分析不能当运行测试」存在张力——它被显式标注为挂账（诚实），但挂账无复测排期。
- **预防**：「代码级放行」必须绑定一个强制复测触发条件（如下一次出包），否则静默烂尾。
